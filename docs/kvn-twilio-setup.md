# KVN Twilio setup

SMS starts disabled. Create/verify the actual legal-owner parent account and isolated KVN subaccount. Select verified toll-free or registered 10DLC sender using verified business details and reviewed charges. Create a Messaging Service with Advanced Opt-Out. Use secure deployment secrets for TWILIO_ACCOUNT_SID, TWILIO_API_KEY_SID, TWILIO_API_KEY_SECRET, TWILIO_AUTH_TOKEN and TWILIO_MESSAGING_SERVICE_SID. Account AuthToken verifies callbacks; sending API key is separate. Never put secrets in chat, browser storage, source, logs or exports.

Public number metadata: TWILIO_SMS_PUBLIC_NUMBER in +1 form. TWILIO_SMS_SENDER_VERIFIED and TWILIO_SMS_CALLBACKS_VERIFIED are operator attestations requiring recorded actual provider/test evidence, not automatic verification. TWILIO_SMS_SENDING_ENABLED defaults false and remains false until account, sender, permission and callback checks succeed. Neither a configured number nor presence of credentials proves sender approval.

Public callbacks will use https://kvnlive.com/api/sms/twilio/status and /api/sms/twilio/inbound. Consent is separate from purchases and email subscriptions. No real SMS, paid resource or registration is authorized merely as a development fixture. A live test requires the chosen authorized number and exact reviewed text.

## Operator activation record

Current integration status: implemented locally; not deployed or activated. No Twilio account, number purchase, registration or real recipient test has been completed by this change.

1. Create the legal owner's Twilio account, then an isolated KVN subaccount. Confirm the actual business identity, billing owner and charges before buying or registering a sender. Future Business Suite customers need separate tenant provisioning and billing; this release only accepts scope `kvn`.
2. Select one approved US/Canada +1 sender. Create its Messaging Service, attach that sender, and enable Advanced Opt-Out. Configure branded confirmation/STOP/HELP copy consistent with `https://kvnlive.com/sms/opt-in` and its privacy/terms links. Set the current disclosure version. Keep the same single sender used by this release's callback identity checks.
3. Store the account SID, sending API key SID/secret, webhook account Auth Token and Messaging Service SID as secure backend deployment secrets. Use only permissions actually supported by the selected Twilio key and account. Keep all three verification/sending flags false while configuring.
4. Set inbound POST URL to `https://kvnlive.com/api/sms/twilio/inbound`. Outbound sends supply `https://kvnlive.com/api/sms/twilio/status?attempt=<opaque-id>` per attempt. The Site must deploy its byte-preserving public gateway after the backend. Provider signatures use this exact public URL and every received form field; JSON, duplicate form keys and invalid signatures are rejected.
5. Record sender approval evidence, Messaging Service ID, Advanced Opt-Out state and callback test evidence in the operator's private setup record. Only then attest `TWILIO_SMS_SENDER_VERIFIED=true` and `TWILIO_SMS_CALLBACKS_VERIFIED=true`. Presence of secrets or a phone number does not prove verification.
6. For the first live test, obtain the owner's exact authorized recipient and message. Temporarily enable sending only when all setup gates pass; use Preview test and Send reviewed test. Confirm the real SID and delivery callback. Verify STOP excludes that number and a newly confirmed START restores permission. Record the results privately; turn sending off if any check fails.

No marketing campaign is a setup test. Release requires the exact preview, recipient count and current permissions. Purchases, email subscriptions and legacy Boolean CRM opt-in without SMS evidence do not grant SMS permission. Unknown START verification stays pending. Signed STOP takes immediate precedence. A STOP arriving after a send has begun cannot recall a message already submitted.

## Operations and limits

Use a single backend instance with the existing persistent data disk. The dispatcher persists `submitting` before a provider POST. An interrupted or unknown result becomes `needs_review`; it is never blindly retried. Campaign History → Check provider delivery statuses reconciles known SIDs using GET only. Unknown attempts without a SID require operator investigation in Twilio; there is no automatic re-send button. Pause stops future claims; accepted messages cannot be recalled. Changing the sender invalidates prior reviewed campaigns and requires a fresh preview.

Limits: 1 new send/second, 1,000 recipients/campaign, 10 segments/message and 10,000 estimated message units/day in America/New_York, including tests and uncertain submissions. GSM extension characters count twice; Unicode estimates use UTF-16 units. Multipart packing preserves whole extension characters and surrogate pairs; toll-free senders use 152 GSM septets or 66 Unicode units per multipart segment, compared with 153/67 for other supported senders. These are estimates and application limits, not guaranteed dollar budgets or provider billing records. Accepted/queued is not delivered; delivered is not read.

History and CSV share exact inclusive-start/exclusive-end filters. At most 10,000 filtered attempts can be exported; narrow the interval if necessary. The UI paginates audience previews and history in pages of 100, including every reviewed recipient and exclusion. History remains accessible beyond 10,000 lifetime attempts; the export limit applies only to the matching CSV report. Sending flags default false on every environment. Rotating keys or changing sender verification invalidates existing reviews; pause before changing account settings.

Official implementation references, rechecked October16 2026: [webhook security](https://www.twilio.com/docs/usage/webhooks/webhooks-security), [Advanced Opt-Out](https://www.twilio.com/docs/messaging/tutorials/advanced-opt-out), [message status](https://www.twilio.com/docs/messaging/guides/track-outbound-message-status). Twilio recommends SDK signature validation. This approved dependency-free implementation instead verifies the complete form signature and is covered by an official signature test vector; review it if the callback format changes.
