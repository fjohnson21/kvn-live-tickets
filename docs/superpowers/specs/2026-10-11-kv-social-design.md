# KV Social isolated pilot

Implements the October 10 approved ecosystem brief and October 11 explicit build request. Latest request names this KV Social, superseding the brief's KB label. Goal: let the owner evaluate a polished phone-first community feed and enforceable review workflow before public launch.

## Boundary
Separate Express app at `social-pilot/server.js`, separate in-memory synthetic store, loopback listener. No imports of ticketing server, customer store, payment, email, CRM or production authentication. Existing npm start and public directory stay unchanged. No deployment or production data migration. Restart discards pilot changes. Only authenticated demonstration accounts may access API data; public registration and real account creation are absent. Demo sessions use independent environment-supplied keys (no defaults), roles assigned on server, expiring HTTP-only same-site cookies and CSRF tokens. A member key represents one shared synthetic member, not production identity.

## Experience
Black/white with restrained red. Editorial wordmark; never invent a replacement crown. Approved crown file must be verified before integration. Chronological feed of clearly labeled sample artist/community editorial posts, zero fabricated engagement, profile cards, artist filtering, reaction toggles, saved posts, sharing and comments submitted for review. Composer supports plain text and a small curated visual theme; arbitrary image/file uploads and external links are disabled in this pilot. All new posts/comments and edits are pending. Published post edits hide the old version until review. Reports are private; block hides an author's posts. My activity shows submission decisions and appeal status. No DMs, video uploads or algorithmic ranking.

## Moderation
Server heuristic screening returns review signals for harassment, hate, threats, spam, derogatory language, personal-information exposure and sexual content. Signals prioritize review; they do not determine guilt. Every submission requires human review even if no signal is detected or screening throws. Owner desk shows pending/reported/removed content, private reports and append-only audit events. Approve, hide, remove, suspend and restore require a reason. Reports do not automatically remove content. Respectful negative opinion/disagreement is explicitly allowed. Members appeal their own removed/hidden content once per decision; owner records an uphold/restore decision and explanation. Owner cannot approve suspended-author content. Owner own-authored submissions cannot be approved by the same owner in this one-owner pilot.

## Safeguards
Allowlisted fields; lengths; Unicode normalization; reject markup, unsafe controls and URLs; textContent rendering. Request body limit, bounded queues and sessions, per-session/account and network rate limits, duplicate submission guard, same-origin and CSRF checks, member/owner access boundaries, no-store and security headers. Production mode refused. No visitor-controlled role or identity fields accepted. Sensitive API responses never cached.

## Before public release
Verify main Network source/hosting and approved crown asset. Prefer social module + versioned API on main hub with one identity provider, not ticket customer reuse. PWA on same origin later; cache only static shell, never authenticated APIs or moderation. Establish verified individual accounts, moderator MFA, invitation cohort, named reviewer and escalation coverage, privacy/terms/age policy, retention/export/delete, durable transactional store and audit history, backups, distributed rate limits, media quarantine/scan/review and classifier evaluation. Carry out security review and real iPhone/Android install and handoff tests. No configuration flag in this demo can safely turn it into production.
