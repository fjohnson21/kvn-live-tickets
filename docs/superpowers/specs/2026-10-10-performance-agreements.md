# Performance agreements design

Preserve the seven existing KV Live signing links and finalized terms. Their original signing site remains authoritative; Command Center imports read-only snapshots and never issues replacement requests. Existing acceptances retain their original identity assurance (typed name/email and possession of a private link), without claiming new email verification retroactively.

New agreements live in a separate permission-restricted, atomically written performance-agreements.json under DATA_DIR. Never write ticket/order storage. Owner-only routes create immutable document versions, approve a recipient/document digest, deliver an individualized 256-bit private link, revoke unsigned requests, inspect evidence, and synchronize statuses. A change requires a new version and fresh approval. Accepted agreements cannot be revised or revoked. Duplicate event/recipient records, including synchronized external records, are blocked.

Before issuing, the owner reviews the exact text and recipient and confirms its hash. Link secrets are stored only as hashes. The public page keeps the token in the URL fragment, uses no third-party content, sets no-store/no-referrer headers, and requires a short-lived, limited-attempt email verification code plus typed-name/email consent. Acceptance is idempotent, bound to the document hash, and retains the exact text, identity, UTC timestamp, user agent, and consent wording.

Email attempts are persisted before network activity; provider acceptance, confirmed delivery, bounced/failed, recorded opens/clicks, page loads, and contractual acceptance are separate facts. A network timeout or interrupted send is unknown and cannot be blindly retried. Provider status refresh is read-only and does not send mail. A retry is allowed only after a definitive rejection, with fresh explicit confirmation. Page views are observed loads, not proof of a human reading.

The existing Site exposes a read-only bearer-secret bridge, with no signing tokens in its payload. It returns complete agreement evidence and view aggregates; new view tracking begins on deployment, never inventing historical views. Command Center validates hashes, identities, unique IDs and timestamps before atomically reconciling all seven records. Missing/changing accepted evidence fails closed. A stale/unconfigured connection is displayed and blocks issuing new requests until reconciliation succeeds.

Security: owner authorization, same-origin mutation checks, strict bounded inputs, rate limits, server-generated IDs/time, expiring token/code, constant-time digest comparisons, output escaping, separate persistent storage, hash validation, and no secrets or performer details committed to Git. Source-site terms, tokens and existing evidence are unchanged.

Verification: unit/integration tests for unauthorized access, CSRF, malformed data, duplicate recipients, immutable versions, stale approval, expiry, identity/code mismatch and lockout, concurrent/replayed acceptance, uncertain delivery and duplicate sends, provider status semantics, external sync failure/idempotency/hash conflicts, escaped rendering and mobile layout. Existing 235-test baseline must remain green. Ship through a feature PR; issuance remains disabled pending deployment configuration and explicit contract approval.
