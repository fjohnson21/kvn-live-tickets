# Unified Kingdom Disciple Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect `www.kvnlive.com/disciples` to the KVN Command Center, add compliant Kingdom Leader direct-team management and Community Bonus accounting, deliver post-approval bundle workflows, and safely complete Briannah Cooper's enrollment without changing existing production ticket or order data.

**Architecture:** The KVN Site remains the branded public form but forwards new applications server-to-server to the Render-hosted Command Center, which becomes the sole source of truth for new applications, approval, identities, teams, commissions and emails. Focused domain modules in the ticketing repository own application validation, team assignments, bonus calculation and bundle actions; `server.js` exposes thin authenticated routes and the existing dashboard calls them. Site D1 records become read-only legacy records after a verified cutover.

**Tech Stack:** Node.js 22, Express 4, Node test runner, JSON persistent store on Render disk, Resend, Stripe; Next.js 16/vinext, TypeScript, Zod, Cloudflare Workers/D1, Vitest and Playwright for `kvnlive.com`.

**Spec:** `docs/superpowers/specs/2026-09-21-unified-kingdom-disciple-design.md`

## Global Constraints

- Public name is **Kingdom Disciple**; plural is **Kingdom Disciples**; internal `disciple` identifiers may remain.
- Agreement v2.2 controls new applications and includes the exact 10%, approved-channel, 30-day attribution, monthly-on-the-15th and no-minimum terms.
- Community Bonus is exactly 2% of eligible gross sales to non-participant customers generated by directly assigned team members only.
- Never pay for applications, enrollment, approval, recruitment, team assignment, participant purchases or second-level activity.
- Joining, approval and Leader consideration remain free; the team-member bundle is optional and post-approval.
- Community Bonus payout is disabled until an owner records licensed-counsel approval through `COMMUNITY_BONUS_LEGAL_APPROVED=true`.
- Existing production ticket, order, payment, attendee, commission and legacy D1 records must not be rewritten or deleted.
- All new collection initialization is additive and must tolerate existing `data/store.json` files that omit the new keys.
- Every mutating owner action records an audit event with actor, action, target, timestamp and relevant non-secret metadata.
- The Command Center deploys and verifies first; the Site cuts over only after its integration endpoint is healthy.

## Review Focus

- A repeated Site submission with the same idempotency key must return the original application reference and create no second record.
- Concurrent or overlapping manual team assignments must leave one effective Leader and preserve the prior assignment history.
- A refund, chargeback or reversal must reverse both the member commission and its related Community Bonus exactly once.
- Participant, complimentary and zero-dollar bundle orders must never create a personal commission or Community Bonus.
- A legal-approval flag that is absent or false must allow bonus calculation previews but block every mark-paid operation.
